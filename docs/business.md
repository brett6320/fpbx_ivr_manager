# Business profile & prompt templates

Admins (`manage_users`) set a **business name**, reusable named **templates**, and
**default destinations** at **`/admin/business`**. The templates become
**placeholders** that can be dropped into any prompt (schedule reason, IVR
greeting, call-flow greeting) — and into other templates — and are plugged in when
the audio is generated.

## Default destinations

Three reusable default destinations — **on-hours** (normal daytime), **off-hours**,
and **emergency** — each chosen from the same destination picker used elsewhere
(extensions, ring groups, IVR menus, voicemail, and **time conditions**), with a
manual-number fallback. The **on-hours** default pre-fills a new time condition's
**open (fall-through) destination**, so a closure schedule naturally falls through
to your normal daytime route (e.g. the office-hours time condition).

## Placeholders

| Placeholder | Value |
|---|---|
| `{business_name}` | The configured business name (falls back to `APP_ORG_NAME` if blank). |
| `{<template>}` | The value of a named template, e.g. `{greeting}`, `{closing}`, `{hours}`. |

Templates are generic — a generic greeting, a closing line, business hours, a
tagline, anything. Add and remove them dynamically on the admin page. Unknown
placeholders are left untouched.

## Nested templating

A template's value may reference other templates (and `{business_name}`), resolved
recursively (cycles are left unresolved rather than looping). For example:

- `opener` = `Thank you for calling {business_name}`
- `closing` = `Thank you for calling and have a nice day`
- `full` = `{opener}. How may we direct your call? … {closing}`

An IVR greeting of `{full}` then renders with the business name and both snippets
substituted in.

## Closure message

The schedule (closure) greeting is assembled as three parts:

```
<opening line>  +  <auto-generated sentence describing the closure window/reason>  +  <closing line>
```

Each closure can also carry an optional **reopen date** (and optional time). When
set, a sentence like `We will reopen on Monday, July 6th at 9:00 AM.` is appended
to the auto-generated middle before the closing line.

The **opening** and **closing** lines are fixed text you configure on the same
admin page (**Closure message**); only the middle sentence varies with the
closure's dates/times. Leave a field blank to use the built-in default:

- **Opening** default — `Thank you for calling {business_name}.`
- **Closing** default — `We apologize for any inconvenience. Please call back
  during our regular business hours, or stay on the line to leave a message.
  Goodbye.`

Both accept `{business_name}` and any template placeholder. Changes apply to
greetings generated afterward (existing recordings are not regenerated).

## Where it applies

Substitution runs on the free-text you author before Text-to-Speech:

- **IVR greeting** (`/ivrs/new`, `/flow/new`)
- **Schedule reason** (`/schedules/new`) — the closed greeting's opening and
  closing lines come from the **Closure message** settings above.

The greeting/reason forms list the available placeholders as a hint.

## Storage

App-managed JSON in the writable state dir (`BUSINESS_CONFIG_FILE`, default
`data/business.json`), written `0600` — no FusionPBX changes; admin-only.
